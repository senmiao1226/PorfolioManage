## Slide 3｜项目背景（1:30）

**讲解词**：

**我们做什么？** 这是一个全栈投资组合管理平台，覆盖持仓管理、行情追踪、业绩分析和可视化展示。

**学习任务**：
- 前后端分离 + REST API 设计
- 持久化层（MySQL + JPA）
- 行情数据集成与可用性保障（缓存/降级）
- 图表展示与交互体验

**开发节奏（4天）**：
- Day1：环境搭建 + 数据模型落库 + 基础接口联通
- Day2：组合/持仓 CRUD + 估值摘要口径对齐
- Day3：行情聚合（多源策略 + 缓存/降级）+ 页面联调
- Day4：分析页 + 可视化 + 统一修复与演示打磨

## Slide 4｜实施思路（2:00）

**讲解词**：

我们的实施思路是**从"闭环"出发**：先跑通主链路，再叠加可靠性与体验。

**主链路**：组合/持仓 → 估值摘要（市值/盈亏/分布）→ 分析（配置/走势/集中度）

**可靠性链路**：价格多源 → 缓存（TTL）→ 故障转移（逐源尝试）

**工程化链路**：Swagger/Health → 配置化（application.yml）→ 文档可复现

## Slide 5｜协作方式（1:30）

**讲解词**：

我们的协作不是简单的前后端切分，而是**端到端亮点共同负责**。

- 组合/持仓 CRUD + 估值口径：Miaofighting 主负责，Sen 协作价格/降级语义
- 行情多源与故障转移：Sen 主负责，Miaofighting 协作估值联动
- Dashboard/Market/Analytics 页面：Miaofighting 主体 + Sen 数据演示，Wwovo 演示脚本对齐
- 踩坑复盘：Wwovo 主负责，全员确认根因与修复

**协作原则**：联调以"页面能跑通 + 数据可解释"为准，遇到外部 API 不稳定先保证降级路径可展示。

## Slide 7｜核心功能（2:00）

**讲解词**：

我们的产品能力覆盖从"总览"到"明细"再到"分析"的一站式体验。

**Dashboard**：KPI 卡片展示总资产、总成本、未实现盈亏、组合数量，还有资产分布条形图和市场概览。

**Portfolio**：支持创建组合、管理持仓、展示估值摘要与资产分布，还能查看股票历史走势。

**Market**：热门股票/指数监控、持仓行情、涨跌榜、搜索与个股详情弹窗。

**Analytics**：资产配置饼图（纯 CSS 实现）、历史走势曲线（SVG）、业绩统计、前 N 大持仓集中度分析。

## Slide 8｜数据模型（2:30）

**讲解词**：

**核心实体**：
- Portfolio（投资组合）：id、name、description、baseCurrency、createdAt
- Holding（持仓）：portfolio_id、assetType、ticker、name、quantity、averageCost、purchaseDate
- AssetType：stock、bond、cash

**关系设计**：Portfolio 与 Holding 是 1:N 关系，使用 JPA @OneToMany + orphanRemoval 级联删除。

**设计原则**：持仓结构化落库，估值/收益/分析按需计算；对外部价格不可用做缓存与降级，保证交互闭环。

---

## Slide 9｜系统架构（1:30）

**讲解词**：

**请求流向**：浏览器（Vue）→ REST API（Controller）→ 业务层 Service → MySQL（JPA）

**估值/行情链路**：Service 调用 PricingService → 外部行情 HTTP 请求 → 内存缓存 → 返回前端展示

这个架构保证了两条核心链路的独立与协作：业务数据链路稳定可靠，行情数据链路灵活可降级。

## Slide 10｜多源行情与故障转移（1:45）

**讲解词**：

**为什么"看起来实时"？**
- 价格缓存 TTL 5 分钟，减少重复请求
- 历史序列 TTL 10 分钟，提升图表加载稳定性

**为什么"不容易坏"？**
- 多数据源优先级 + 故障转移：Cached API → Yahoo Finance → 新浪财经
- 逐源尝试：主源失败则继续下一个 provider
- 按股票类型选择 provider，减少无效调用

**降级语义**：如果最终仍不可用，后端返回空/"—"，前端不崩溃，页面保持可用。

## Slide 11｜现场演示（8:00）

**讲解词**：

接下来进行现场演示，路径是 Dashboard → Portfolio → Market → Analytics。

**1. Dashboard（约 90 秒）**
展示总资产、总成本、未实现盈亏、组合数量、资产分布条形。
讲点：Dashboard 通过聚合多个接口并行加载，让"总览"快且稳定。

**2. Portfolio（约 90 秒）**
展示组合摘要（总成本/总市值/盈亏）与持仓明细。
讲点：估值口径在后端统一（cash 按面值，其他用 quantity * price；price 不可用走降级）。

**3. Market（约 90 秒）**
展示搜索股票详情弹窗、热门股票列表、持仓涨跌榜。
讲点：价格由多源+缓存提供；失败不影响页面结构。

**4. Analytics（约 90 秒）**
展示资产配置饼图（纯 CSS conic-gradient）、SVG 折线走势、业绩统计面板。
讲点：前端用轻量 SVG 展示历史走势；切换时间范围并刷新数据。

## Slide 13｜挑战与反思（1:45）

**讲解词**：

我们踩过哪些坑？怎么修？下次怎么做更好？

**NPE（空指针）**：外部 API 返回空时直接计算 quantity * marketPrice 导致崩溃。修复：用 Optional + 降级方案（不可用时使用成本或空值逻辑）。

**CORS 跨域**：浏览器拦截 fetch 请求。修复：后端 CORS + 前端 Vite proxy 双保险。

**日期格式不一致**：后端 Instant 序列化与前端解析不一致导致 Invalid Date。修复：统一 ISO 8601 / JsonFormat 口径。

**double 精度问题**：浮点计算误差累计影响显示。改进：四舍五入到固定小数位（round4/round2）并在关键口径处统一。
